# P5 阶段小结 — 占用率预测（数据 / 训练 / 推理 / 管理端）

> 日期：2026-11-25 ｜ 对应 tag：v0.6.0 ｜ 目标：可复现的训练数据 → 可对比的模型指标 → 可调用的预测接口 → 可视化页面

## 一、数据集（固定 seed 可复现）

| 项 | 内容 |
|---|---|
| 规模 | 3 个场景停车场 × 42 天 × 24 小时 = **3024 行**小时级样本 |
| 场景 | 科技园办公（120 位）/ 万象城商业（200 位）/ 滨海住宅（80 位），各带典型日曲线 |
| 业务因素 | 工作日/周末系数、国庆假期（10-01~10-07）系数、自相关平滑（`0.65×前值 + 0.35×目标 + 噪声`） |
| 字段 | lot_id、capacity、timestamp、occupancy_rate、occupied、free |
| 滚动更新 | 数据截止到「当前整点」，超过 24 小时自动重建，保证滞后特征不过期 |

> 生成器在 `ai/app/prediction/dataset.py`，真实上线时把 `load_dataset` 换成 `parking_record` 的按小时聚合即可，特征与训练代码不用改。

## 二、特征工程（18 维）

- 时间：hour、weekday、is_weekend、is_holiday
- 周期编码：hour_sin/cos、weekday_sin/cos（解决 23 点与 0 点不连续）
- 滞后：lag_1、lag_2、lag_24、lag_168（同小时上周）
- 滚动：roll_3、roll_24（均基于 shift(1)，杜绝目标泄漏）
- 静态：capacity + 停车场 one-hot（lot_1~lot_3）

训练/测试按时间切分：最后 7 天为测试集，其余为训练集（**不做随机切分**，避免未来信息泄漏）。

## 三、模型与指标

| 模型 | MAE | RMSE | R² |
|---|---|---|---|
| RandomForest (200 树) | 2.57% | 3.32% | 0.9835 |
| **XGBoost（最佳）** | **2.47%** | **3.15%** | **0.9852** |
| 基线（上周同时刻） | 3.74% | — | — |

- 相比朴素基线 MAE 降低 **约 34%**

- 产物：`ai/models/occupancy_xgb.joblib`（或 rf）+ `model_meta.json`（特征顺序、指标、场景、训练时间）

## 四、推理接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/predict/occupancy` | `{lotId, startTime?, hours(1-48)}` → 逐小时 `predictedRate / predictedOccupied / freeSpaces` |
| GET | `/predict/model/info` | 模型就绪状态、指标、基线、场景列表 |

实现要点：
1. **递归多步预测**：逐小时滚动更新 lag_1/lag_2/roll_3 等短期特征，使 24h 曲线保持连续性
2. **惰性训练 + 内存缓存**：模型缺失时自动训练一次；训练后需重启服务才会加载新模型（已在文档注明）
3. **异常分级**：未知停车场 404、参数非法 422、训练/推理失败 503（不抛 500 堆栈）
4. **范围约束**：输出裁剪到 0~1，占用车位取整并保证 `occupied + free = capacity`

实测 24h 曲线（办公场景）：夜间 8.5% → 07:00 起爬升 → 14:00-17:00 峰值 87% → 22:00 回落 36%，符合办公停车场规律。

## 七、踩坑记录（含一个真实线上 bug）

| 问题 | 原因 | 处理 |
|---|---|---|
| 预测峰值只有 17% | 数据集固定结束在 10-25，滞后特征隔了一个月，递归预测沿着旧 lag 漂移 | 数据集滚动到当前整点，过期 24h 自动重建；峰值恢复到 87% |
| 特征维度 19 而非 18 | `lot_id` 也以 `lot_` 开头被当成 one-hot 列 | 排除 `lot_id` |
| `/predict/model/info` 500 | meta 里字段是 `lot_id`，Pydantic 模型要 `lotId` | 接口层做字段映射 |
| **入场后立即查询/离场 500** | MySQL `DATETIME` 无小数秒，毫秒进位使 `entry_time` 比当前时间晚 <1 秒，计费引擎判为"离场早于入场" | 写入时间截断到秒；读取侧对"未来入场时间"做兜底；88 个后端测试回归通过 |
| 管理端场景与业务停车场 ID 不一致 | 模型用合成场景 lotId 1/2/3，业务库 ID 是真实自增 | 页面改用 `/model/info` 返回的场景列表并标注口径 |
