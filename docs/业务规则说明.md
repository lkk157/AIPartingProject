# 业务规则说明

> 汇总系统当前生效的关键业务规则，便于需求说明与答辩讲解。每条规则都有对应测试。

## 1. 预约规则

| 规则 | 说明 | 失败提示 |
|---|---|---|
| 整点时段 | 开始时间必须是整点，时长 1-4 小时 | 预约需按整点开始 |
| 未来时间 | 开始时间必须晚于当前时间 | 预约开始时间必须晚于当前时间 |
| 单预约限制 | **同一车主同时只能有 1 条「待使用」预约** | 您已有待使用的预约，请先使用或取消后再预约 |
| 过期自动作废 | 已过结束时间的历史「待使用」预约，在下一次预约时自动置为「已过期」并释放车位 | — |
| 车位互斥 | 同一车位同一时段只能有一条有效预约（区间重叠校验 + 唯一索引） | 该时段已被预约 |
| 取消 | 仅未开始的待使用预约可取消，取消后释放车位 | 预约已开始，无法取消 |
| 入场窗口 | 可在预约开始前 60 分钟至预约结束之间入场 | 不在预约可用时段内 |

### 单预约限制的实现方式（并发安全）

1. `SELECT id FROM user WHERE id = ? FOR UPDATE` —— 锁住该用户行，把同一车主的预约请求串行化；
2. **加锁读** `SELECT id FROM reservation WHERE user_id = ? AND status = 0 LIMIT 1 FOR UPDATE`
   —— 必须用当前读，否则 REPEATABLE READ 快照看不到其他事务刚提交的预约（这是实测踩到的坑）；
3. 无有效预约时再走车位条件更新（`FREE → RESERVED`）与唯一索引兜底。

并发验证：同一车主 10 个线程同时预约 2 个不同车位 → **1 成功 / 9 拒绝**，库中仅 1 条预约。

## 2. 车位状态机

```
空闲 FREE ──预约──> 预约锁定 RESERVED ──入场──> 占用 OCCUPIED ──离场──> 空闲
   │                    │                        │
   └──维护──> 维护中 MAINTENANCE <──维护──────────┘（仅空闲/占用可进维护，维护只能回空闲）
```

- 所有流转使用条件更新（`WHERE status = 期望值`），非法流转直接拒绝
- 车位状态变更是并发闸门：10 线程抢同一车位仅 1 个能改成功

## 3. 计费规则

| 步骤 | 规则 |
|---|---|
| 免费时长 | 停车场规则中的 `free_minutes`（默认 15 分钟）内离场不收费 |
| 首小时 | 超出免费时长即收首小时费用（默认 6 元） |
| 超出部分 | 按小时计，不足 1 小时按 1 小时（默认 4 元/小时） |
| 封顶 | 每 24 小时封顶（默认 40 元）；跨天按天数分别封顶 |
| 金额单位 | 全程整数分（`amount_cents`），杜绝浮点误差 |
| 时间口径 | 入场/离场时间写入数据库前截断到秒（MySQL DATETIME 毫秒会进位，曾导致"离场早于入场"） |

## 4. 订单与支付

- 离场自动生成订单：待支付（0）→ 已支付（1）/ 已取消（2）
- 金额为 0（免费时段）的订单直接置为已支付并记录支付时间
- 支付使用条件更新（`WHERE status = 0`），重复支付返回 400
- 终态订单不可再次变更（状态机集中校验）

## 5. 权限

| 角色 | 权限范围 |
|---|---|
| USER | 停车场查询、预约、入场/离场、自己的订单 |
| PARKING_ADMIN | 所绑定停车场的车位/规则维护、预约与订单查看 |
| SYS_ADMIN | 全部停车场、用户管理、运营看板、AI 预测 |

越权访问返回 403；未登录 401 并由前端跳转登录页。
