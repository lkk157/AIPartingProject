## 1. 仓库结构与 Git 工作流

### 1.1 Monorepo 结构

```
AIPartingProject/
├── server/            # Spring Boot 3 业务后端
├── ai/                # FastAPI：预测 + LangChain Agent + RAG
├── admin/             # Vue3 + TS + Element Plus 管理端
├── app/               # uni-app 用户端（H5 + 微信小程序）
├── infra/             # docker-compose.yml、初始化 SQL、nginx 配置
├── docs/              # 阶段文档、ER 图、接口文档、实验报告
├── .github/workflows/ # CI：三端测试
└── README.md
```

### 1.2 分支与提交规范

- `main` 保持随时可运行；开发在 `feat/pN-简述` 分支（如 `feat/p3-reservation`）
- 提交信息：`type(scope): 描述`，type ∈ feat / fix / test / docs / refactor / chore
  例：`feat(p3): 预约创建增加时段容量校验与唯一约束`
- **每阶段闭环**：分支开发 → 本地测试全绿 → push 分支 → PR 自查合并 main → 打 tag → `git push --tags`
- 阶段内允许频繁小提交，但合并 main 前必须测试全绿

### 1.3 CI（P0 建立，后续每阶段自动守护）

GitHub Actions 三个 job：
- `server-test`：JDK 17 + `./mvnw -B test`
- `ai-test`：Python 3.11 + `pytest`
- `web-test`：Node 22 + `npm run test`

CI 红 = 阶段未完成，禁止打 tag。

### P1 认证与权限（W2）

**功能**
- 表：`user` / `role` / `user_role`

**单元测试**

- 登录集成测试：成功 / 密码错误 / 用户禁用 → 各自状态码
- RBAC：普通用户访问管理端接口 → 403；管理员 → 200
- 注册：重复用户名、重复手机号、非法参数 → 400

**完成门槛**：以上全绿 + tag v0.2.0

### P3 预约 / 入场离场 / 计费 / 支付（W3）

**功能**
- `reservation`：创建（时段校验、容量校验、唯一约束防重复）、取消、过期处理、状态机
- 模拟入场（创建 `parking_record`，车位置为占用）、模拟离场（释放车位、生成 `parking_order`）
- **计费引擎**：免费时长、阶梯单价、封顶、跨时段/跨日计算
- `payment_record` 模拟支付；订单状态机（待支付/已支付/已取消）
- 订单与预约查询、费用明细

**单元测试（本阶段测试密度最高）**
- 计费引擎边界值表：0 分钟、免费时长内、精确跨 1 分钟、封顶触发、跨日停车 —— 每条一个用例
- **预约并发**：10 线程抢同一停车场同时段 → 仅 1 条成功（真实 MySQL `parking_test` + 唯一约束验证）
- 状态机：已取消预约不能入场；未支付订单不能完成离场
- 订单金额 == 计费引擎独立计算结果（防两处逻辑不一致）
- 时段重叠校验：跨界预约被拒

**完成门槛**：以上全绿 + tag v0.4.0

### P5 占用率预测（W5）

**功能**
- 数据管线：UCI 下载 → 清洗（缺失/异常/去重）→ 按停车场分组 → 时间特征 + 滞后特征
- 时间顺序划分 train/val/test（禁未来信息泄漏）
- 基线（历史均值）+ Random Forest + XGBoost；评估 MAE/RMSE/MAPE/R²
- 模型持久化（joblib）→ `/internal/predictions/{lot_id}?horizon=30|60|120`
- admin 预测图表页；实验报告写入 docs/

**单元测试**
- 清洗：缺失值填充规则、异常值剔除、去重断言
- **特征无泄漏**：滞后特征 shift 正确性断言（t 时刻特征不含 t 之后数据）
- 指标函数：固定数组 → 手算值对照（MAE/RMSE/MAPE/R²）
- API：响应 schema 校验；模型未加载 → 503；horizon 非法 → 400
- 模型产物可加载并推理（smoke）

**完成门槛**：以上全绿 + 实验报告产出 + tag v0.6.0

### P6 LangChain Agent（W6）

**功能**
- AI 服务接线：ChatOllama(qwen2.5:7b)、`with_structured_output` 意图解析（目的地/预算/时长/时间）
- 8 个 `@tool`：search / availability / fee / predict / compare / history / create_reservation / cancel_reservation（全部 httpx 回调 Spring Boot，AI 不直连 MySQL）
- LangGraph `create_react_agent` 编排，`max_iterations=5`
- 两阶段确认：create_reservation 仅返回草案 + 确认卡片；确认接口二次校验落库
- SSE 流式（astream_events）、会话落库、工具审计日志（工具名/参数/耗时/结果摘要）
- 降级开关 `AI_ENABLED`

**单元测试**
- 工具单测：respx mock 后端 → 正常/404/403/超时 分支；Pydantic 参数 schema 拒绝非法入参
- **权限注入**：构造模型返回含 `user_id=他人` 的 tool args → 断言被服务端注入值覆盖
- 意图解析：FakeChatModel 固定输出 → 槽位断言；解析失败 → 降级普通搜索
- Agent 循环：FakeListChatModel 两步（工具调用 → 最终回答）→ 断言工具被执行、迭代计数正确；超限 → 兜底
- 越权：cancel 他人预约 → 403 正确透出、不泄露订单信息
- SSE：事件序列符合约定（start/delta/tool/end）

**完成门槛**：以上全绿 + tag v0.7.0

## 3. 测试基础设施约定

| 端 | 技术栈 | 用途 |
|---|---|---|
| server | JUnit5 + Mockito | service 层纯单测 |
| server | MockMvc + 真实 MySQL（parking_test） | 控制器/参数校验/权限矩阵集成测试 |
| server | 真实 MySQL（本地 compose 或 CI service container） | 事务/并发/唯一约束（仅 P3 并发类） |
| ai | pytest + pytest-asyncio | 全量 |
| ai | respx | mock 后端 HTTP |
| ai | FakeListChatModel / FakeChatModel | Agent 编排测试，不依赖真 LLM |
| admin/app | vitest + @vue/test-utils | 工具函数/接口封装/store 优先，组件测试按余量 |

**覆盖率原则**：service 与 tool 层 ≥70%，计费引擎/权限/状态机 100% 分支覆盖；不追总覆盖率数字。
**测试命名**：`should_预期_when_条件`，一个用例一个断言主题。
